# Issue 15 — grill-me-json skill authoring & testing

## Context

The grill-me-json skill is a standalone skill that reproduces grill-me's
semantics exactly (design tree, frontier, rounds, caps, recap, recommendation,
reminder, closing legend) except the output medium: instead of rendering
markdown in chat, it calls the grill-chef MCP tools with JSON payloads. The
skill sources live in this repo under `skills/grill-me-json/`.

Per the writing-skills Iron Law: no skill without a failing test first. The
skill must be baseline-tested with pressure scenarios (subagents without the
skill violating round caps, inventing questions, dropping reminders), then
written, then re-tested under pressure, then refined to close loopholes.

Referenced in grill rounds: R1 (Q1.5 separate grill-me-json, standalone,
no reference to grill-me), R4 (Q4.2 writing-skills guidelines, tool naming,
Iron Law testing gate), R5 (Q5.1 no stop tool clause in skill prose).

## Requirements

### Skill structure

```
skills/grill-me-json/
  SKILL.md          # Main reference (required)
  api.md            # JSON payload reference (issue 3 schema, heavy reference)
```

### SKILL.md frontmatter

- `name`: `grill-me-json`
- `description`: Triggering conditions only, starts with "Use when...",
  third person. Must NOT summarize the skill's workflow (SDO trap). Example:
  "Use when grilling a plan over rounds with the grill-chef UI available and
  the user wants structured interactive questioning."
- Under 500 characters if possible.

### SKILL.md content

The skill body reproduces grill-me's semantics:

- **Glossary**: design tree, frontier, retained, recap, abstract, reminder,
  legend (same as grill-me).
- **Rounds**: cap at 5 questions per round, 5 choices per question, up to 5
  rounds. Retained questions carry to later rounds. Each round's answers
  reshape the tree and recompute the frontier.
- **Round format**: same structure as grill-me (intro, recap branches,
  question blocks with abstract, options, recommendation, reminder).
- **Facts vs. decisions**: dispatch sub-agents for facts, never ask the user
  for lookable information.
- **Closing**: legend with per-branch tagged bullets. Wait for user
  confirmation in chat before acting.
- **MCP integration**: instead of outputting markdown, the agent:
  1. Calls `grill_start` with a session name.
  2. Calls `grill_round` with the round JSON payload (issue 3 schema).
  3. Waits for the tool result (answers).
  4. Repeats for each round.
  5. Calls `grill_round` with a legend payload on the final round.
  6. If the tool times out, calls `grill_recover` to resume.
- **No stop clause**: explicit statement that the agent has no capability to
  stop or restart the server; `grill_start` and `grill_recover` are
  idempotent re-starts only.
- **api.md cross-reference**: the skill references `api.md` for the JSON
  payload shapes rather than inlining them (token efficiency, keeps SKILL.md
  compact).

### api.md content

- The full JSON schema from issue 3 (round payload, legend payload, result
  payload).
- Tool parameter shapes for `grill_start`, `grill_round`, `grill_recover`.
- Caps enforcement rules.

### Testing gate (writing-skills Iron Law)

1. **RED**: Run pressure scenarios with subagents WITHOUT the skill:
   - Agent must grill a plan; observe if it violates round caps, invents
     questions outside the frontier, drops reminders, skips the legend.
   - Document exact rationalizations verbatim.
2. **GREEN**: Write the skill addressing those specific violations. Re-run
   the same scenarios WITH the skill. Agent should now comply.
3. **REFACTOR**: Find new rationalizations, add explicit counters, re-test
   until bulletproof.
4. **Micro-test wording**: Before full pressure scenarios, verify the
   description field and key instructions with 5+ fresh-context samples.

## Dependencies

## Acceptance criteria

- `skills/grill-me-json/SKILL.md` exists with correct frontmatter.
- `skills/grill-me-json/api.md` documents the JSON schema and tool shapes.
- The skill reproduces all grill-me semantics (rounds, caps, frontier,
  recap, recommendation, reminder, legend, facts vs decisions, closing).
- The skill specifies MCP tool calls instead of markdown output.
- The "no stop tool" clause is present.
- Baseline pressure scenarios were run and documented before writing.
- Post-skill pressure scenarios show compliance.
- SKILL.md is under 500 words (excluding api.md).
