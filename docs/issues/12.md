# Past-round immutable rendering

## Context

Previous rounds (round number < current) are read-only by design. The user can view them in the browser but cannot edit answers or comments. This is a routing/rendering decision — the server renders static pages with no edit widgets — not a client-side disable trick. The boundary is per-round: the current round's questions are fully editable (issue 10), past rounds are fully static.

Referenced in grill rounds: R1 (Q2.5 comments read-only means immutable), R3 (Q3.4 all questions of ongoing round accessible from sidebar), R5 (Q5.3 past-round routes render immutable by construction).

## Requirements

- Routes `/s/<id>/r/<n>` and `/s/<id>/r/<n>/q/<m>` for `n < current_round`
  render as **static pages**:
  - Question title, abstract (markdown rendered).
  - Selected choice text (or "Skipped" badge).
  - Comments as plain text (no add/remove buttons).
  - No radio buttons, no comment inputs, no Next/Skip buttons.
- The sidebar lists past rounds as plain links (no "edit" affordance).
- The server decides immutability based on the round's status in state (`submitted`), not on client-side logic.
- Within the current round: all questions are editable via the sidebar (issue 10). The boundary is: submitted round = immutable, pending round = editable.
- No "copy to clipboard" or "download JSON" buttons in the initial scope (could be added later at the UI-implementation stage without reopening the design tree).

## Dependencies

- Issue #1 (state database — round status determines immutability)
- Issue #8 (HTML routes — routes render differently based on round status)

## Acceptance criteria

- A submitted round renders as a static page with no interactive widgets.
- A pending (current) round renders with full edit widgets.
- The sidebar shows past rounds as read-only links.
- No client-side "disable" logic — the server template omits widgets entirely for past rounds.
- Attempting to POST to a past round's answer endpoint returns an error.
