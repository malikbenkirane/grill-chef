# Issue 3 — JSON round payload schema

## Context

The `grill_round` tool sends only the current round's JSON to the server.
Earlier rounds live in state; screens render from state. The schema must
carry both structured data (for widget binding) and markdown prose blocks
(for rendering). This is a design specification issue — no code, just the
contract that issues 4, 5, 8, 10, 11, 13, and 15 depend on.

Referenced in grill rounds: R3 (Q3.3 drive_round sends current round only,
markdown blocks translated to HTML at render time), R4 (Q4.3 structured
envelope + markdown inline boundary).

## Requirements

### Round payload (sent by agent via `grill_round`)

```
{
  "session_id": "<id>",
  "round": {
    "number": 1,
    "intro": "<markdown: 3-5 sentence intro paragraph>",
    "recap_branches": [
      {
        "tag": "<short tag>",
        "title": "<branch title>",
        "prose": "<markdown: 3-5 sentence summary>",
        "newly_settled": ["<tag>", "<tag>"],
        "frontier_remaining": "<k> questions (<j> served; rest retained)"
      }
    ],
    "questions": [
      {
        "id": "Q1.1",
        "title": "<question title>",
        "abstract": [
          "<markdown paragraph 1>",
          "<markdown paragraph 2>",
          "<markdown paragraph 3 (optional)>"
        ],
        "options": [
          {
            "id": 1,
            "text": "<markdown: option label, inline emphasis allowed>"
          },
          {
            "id": 2,
            "text": "<markdown>"
          }
        ],
        "recommended_index": 0,
        "reminders": [
          { "tag": "<tag>", "summary": "<one-phrase summary>" }
        ]
      }
    ]
  }
}
```

### Legend payload (optional, final round)

```
{
  "session_id": "<id>",
  "legend": {
    "title": "<tree topic>",
    "branches": [
      {
        "title": "<branch title>",
        "bullets": [
          { "tag": "<tag>", "decision": "<settled decision>, because <reason>" }
        ]
      }
    ]
  }
}
```

### Round result (returned by `grill_round` when user submits)

```
{
  "session_id": "<id>",
  "round_number": 1,
  "answers": [
    {
      "question_id": "Q1.1",
      "choice_id": 2,
      "skipped": false,
      "is_other": false,
      "comments": ["<comment text>", "<comment text>"]
    }
  ],
  "round_status": "submitted"
}
```

### Structural vs markdown boundary

- **Structural (machine-readable, widget-binding):** round number, question
  ids, option ids, `recommended_index`, reminder tags, answer choice ids,
  skipped flag, is_other flag.
- **Markdown blobs (server renders to HTML):** intro, abstract paragraphs,
  recap prose, option label text, comment text, legend bullets.
- Option labels may contain inline markdown (bold, links) but the option
  count and recommended marker are structural fields, never inside prose.
- Tags are plain strings (short identifiers), not markdown.

### Caps

- 5 questions max per round, 5 options max per question, up to 5 rounds per
  session. Rounds keep arriving while the frontier is unresolved.

## Dependencies

None — this is a pure design specification.

## Acceptance criteria

- A round payload can express every element of grill-me's markdown round
  format (intro, recap branches, question blocks with abstract, options,
  recommendation, reminders).
- The legend payload can express the per-branch tagged bullets closing format.
- The result payload carries enough information for the agent to recompute
  the frontier (choice, skipped, other, comments per question).
- Schema is valid JSON and parseable by Go stdlib `encoding/json`.
