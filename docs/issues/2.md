# Session identity & URL namespacing

## Context

Multiple agents may call the MCP server simultaneously, each starting or driving a different grill. Sessions must be unambiguous in the browser: each has a server-minted id embedded in the URL path, and a human-readable name for tab/heading display.

Referenced in grill rounds: R2 (Q2.3 /s/<id>/ prefix), R3 (Q3.3 start_grill accepts a session name), R4 (Q4.5 session denomination).

## Requirements

- Session id is minted server-side by the `grill_start` tool call (issue 4), not by the agent.
- The agent keeps the session id in its chat history and passes it on all follow-up tool calls (`grill_round`, `grill_recover`).
- URL scheme: `/s/<id>/r/<n>` for round screens, `/s/<id>/r/<n>/q/<m>` for question screens, `/s/<id>/` for session root.
- `start_grill` accepts a `name` string used as the browser tab title and page heading (session denomination).
- Session ids are opaque to the agent — no structure to parse, just a token to echo back.
- Ids should be short enough for URLs but unique enough to avoid collisions across concurrent sessions (e.g., 8-12 char base62).

## Dependencies

- Issue #1 (state database — sessions are stored here).

## Acceptance criteria

- Two concurrent sessions have different ids and different URL paths.
- A session id passed to `grill_round` or `grill_recover` retrieves the correct session from state.
- The browser tab title and page heading show the human-readable session name.
- URLs are stable: the same session id always maps to the same `/s/<id>/` path prefix.
