# MCP tool: grill_recover

## Context

Grill stations can stall for hours or days. If a `grill_round` tool call times out or the agent's chat context is lost, the user may ask the agent to recover the session. This tool checks the state cache for pending answers, and if none are submitted, re-opens the browser for that session — same drill as the first time.

Referenced in grill rounds: R2 (Q2.2 recovery tool re-opens browser), R4 (Q4.2 grill_recover auto-opens browser), R5 (Q5.1 agent cannot stop, only idempotently restart).

## Requirements

- Tool name: `grill_recover`.
- Input parameters:
  - `session_id` (string, required): the session id to recover.
- Behavior:
  1. Look up the session in state (issue 1). If not found, return an error.
  2. Check the current round's status:
     - If `submitted`: return the round result (issue 3 schema) immediately. The agent already has the answers and can proceed to the next round.
     - If `pending` (user hasn't submitted): ensure the daemon is running (issue 7), re-open the browser to the session's current round URL, and **block** until the user submits (same as `grill_round`'s blocking behavior).
  3. If the session is `closed`: return the legend (if stored) or a "session closed" message.
- The agent's only lifecycle interaction is idempotent restart: if the daemon is alive, nothing happens; if stale, respawn. The agent has no stop capability (issue 7, Q5.1).
- Progress/keepalive notifications apply during the blocking wait, same as `grill_round`.

## Dependencies

- Issue #1 (state database — check session and round status)
- Issue #2 (session identity — session_id parameter)
- Issue #4 (grill_start — session must have been created)
- Issue #5 (grill_round — may resume a pending round's blocking wait)
- Issue #7 (daemon HTTP listener — must be running for browser to work)

## Acceptance criteria

- Calling `grill_recover` on a session with a pending round re-opens the browser and blocks until submit, then returns the answers.
- Calling `grill_recover` on a session with a submitted round returns the answers immediately without opening the browser.
- Calling `grill_recover` on a non-existent session returns a clear error.
- Calling `grill_recover` on a closed session returns the legend or a "closed" message.
- The agent cannot stop or kill the daemon through this tool.
