# Server-rendered HTML routes & templates

## Context

The daemon HTTP listener (issue 7) serves browser pages using Go stdlib templates (`html/template`) with small vanilla-JS progressive enhancement. All screens render from state (issue 1) — the server does not hold per-request session data. Routes follow the `/s/<id>/` URL scheme (issue 2) and the mockup screens A through E.

Referenced in grill rounds: R1 (Q1.3 server-rendered + vanilla JS), R3 (Q3.3 screens render from state), R4 (Q4.5 subcommands: ui opens station home).

## Requirements

### Routes

| Route | Screen | Description |
|-------|--------|-------------|
| `/` | Station home (issue 14) | Lists pending + historical sessions, dismiss |
| `/s/<id>/` | Session root | Redirects to current round |
| `/s/<id>/r/<n>` | Round intro (screen A/B) | Round intro, recap branches, sidebar |
| `/s/<id>/r/<n>/q/<m>` | Question screen (screen C/D) | Abstract, options, widgets, comments |
| `/s/<id>/r/<n>/final` | Recap/submit (screen E) | Review all answers, submit button |
| `/s/<id>/legend` | Legend screen (issue 13) | Final legend rendering |

### Rendering rules

- All rendering reads from state (issue 1); no per-request session data.
- Markdown blobs in the payload (issue 3) are translated to HTML by the server at render time using a minimal markdown renderer (inline emphasis, paragraphs, bullet lists). No external markdown library — a small inline renderer or stdlib-compatible approach.
- Past rounds (`<n` < current) render as **static immutable pages**: choice + comments as on-screen text, no edit widgets (issue 12).
- The current round renders interactive widgets (issue 10).
- Sidebar (mockup A/B hamburger): per-grill rounds only. Previous rounds are listed as read-only links. No planned-round placeholders (frontier is answer-dependent). Global session index lives at `/` (issue 14).
- Stdlib `html/template` for all pages; templates escape user content safely.

### POST endpoints

| Endpoint | Action |
|----------|--------|
| `POST /s/<id>/r/<n>/q/<m>/answer` | Save answer for question m (autosave) |
| `POST /s/<id>/r/<n>/submit` | Submit round (screen E), freeze answers |
| `POST /s/<id>/r/<n>/q/<m>/comment` | Add a comment to question m |
| `DELETE /s/<id>/r/<n>/q/<m>/comment/<i>` | Remove comment i from question m |

## Plan prep — store/concurrency notes (from issue 1 grill)

- `docs/issues/1.md` now settles a **dual-writer topology**: MCP (stdio) owns sessions/questions/round-payloads; this issue's daemon owns answers/comments and `round.status`. WAL + `busy_timeout` are set in the store's setup DDL (issue 1).
- Rendering must never mutate state beyond its owned paths: past-round pages are static, current-round autosave only writes `answers`/`comments` rows. Stale-tab writes are rejected via state reads, not client-side badges (issue 12).
- A stale browser tab autosaving against a submitted round must be rejected server-side, keeping issue 12's immutability guarantee.

## Acceptance criteria

- All routes return valid HTML pages rendered from state.
- Markdown blobs render as formatted HTML (bold, paragraphs, bullets).
- Past-round routes show no edit widgets; current-round routes do.
- Sidebar lists rounds of the current session only, no placeholders.
- POST endpoints save answers/comments to state and return success.
- Submit endpoint freezes the round's answers as immutable.
