# Tailwind build pipeline & theming

## Context

The UI needs dark/light mode support and faithful mockup implementation (chips, cards, buttons, modals). Tailwind CSS provides utility classes for this, but per the stack rule (Q1.4 "as few external deps as possible"), Tailwind must be a build-time asset only — generated CSS committed to the repo, zero Go-side dependencies, self-contained binary preserved.

Referenced in grill rounds: R4 (Q4.5 Tailwind CSS + dark/light modes with switch), R5 (Q5.2 build-time asset, vendored standalone binary, generated CSS committed, localStorage theme persistence).

## Requirements

- **Tailwind standalone CLI**: vendored under `bin/tailwind` (the standalone binary, no npm/node required). A `//go:generate` directive regenerates CSS from template class usage, keeping the pipeline within Go tooling.
- **Generated CSS committed**: the output `web/static/css/app.css` is checked into the repo. The Go binary embeds it via `embed.FS`. Re-running `go generate` is only needed when template classes change.
- **Dark/light mode**: CSS variables or Tailwind's `dark:` variant with a class toggle on `<html>`. A switch in the UI toggles the class.
- **Theme persistence**: `localStorage` in the browser (per-device, no server-side theme state). Default to `prefers-color-scheme` on first visit.
- **No Go dependency**: Tailwind is purely a build-time tool; the Go binary serves only static CSS.
- **`//go:generate` directive**: placed in the package that owns the CSS embed (e.g., `web/static/static.go`); runs `bin/tailwind` to scan templates and regenerate `app.css`. No Makefile required.

## Dependencies

- Issue 8 (HTML routes & templates — templates define which Tailwind classes are used)

## Acceptance criteria

- `app.css` is present in the repo and served by the Go binary.
- Dark/light switch toggles the theme and persists across page reloads via localStorage.
- `go generate ./...` regenerates `app.css` from template class usage.
- No npm/node required to build the Go binary (CSS is pre-generated).
- The Go binary has zero CSS-related Go dependencies.
