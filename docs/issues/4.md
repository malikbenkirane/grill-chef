# Issue 4 — MCP tool: grill_start

## Context

The first tool in the grill-chef MCP surface. Creates a new grill session,
mints a session id, stores it in the state database, accepts a human-readable
session name, and ensures the HTTP daemon is running so the browser UI is
reachable. Returns the session id and the browser URL to the agent.

Referenced in grill rounds: R2 (Q2.1 first MCP tool generates session id),
R3 (Q3.3 start_grill accepts session name), R4 (Q4.2 namespace-prefixed
verb-first tools).

## Requirements

- Tool name: `grill_start` (namespace prefix groups grill-chef tools in
  clients' tool pickers).
- Input parameters:
  - `name` (string, required): human-readable session name shown as browser
    tab title and page heading.
- Behavior:
  1. Mint a unique session id (see issue 2).
  2. Create a session record in the state database (issue 1) with status
     `active`, the given name, and created_at timestamp.
  3. Ensure the HTTP daemon is running (issue 7): check state db for pid +
     port; if alive, reuse; if stale or absent, spawn a detached daemon child.
  4. Attempt to auto-open the browser to the session URL.
  5. Return the session id and the URL as the tool result.
- The tool call returns immediately (non-blocking) — it does not wait for
  the user to do anything. The blocking wait happens in `grill_round`
  (issue 5).
- Idempotent re-start: if called again with the same session id (should not
  happen in normal flow, but defensively), return the existing session's URL
  without creating a duplicate.

## Dependencies

- Issue 1 (state database — session storage)
- Issue 2 (session identity & URL namespacing)
- Issue 7 (daemon HTTP listener — must be running for URLs to resolve)

## Acceptance criteria

- Calling `grill_start` with a name returns a session id and a valid
  `http://localhost:<port>/s/<id>/` URL.
- The session appears in the state database with the correct name and
  `active` status.
- The HTTP daemon is running after the call (pid + port recorded in state).
- Browser auto-open is attempted; URL is always returned as fallback.
- A second call does not create a duplicate session or duplicate daemon.
