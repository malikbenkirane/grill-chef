# Issue 10 — Question screen widgets

## Context

The question screen (mockup C/D) is where the user answers each question of
the current round. It carries exclusive-choice radio buttons, a multi-comment
list with add/remove, an "Other" option requiring at least one comment, and
Next/Skip navigation buttons. Debounced autosave provides a "Saved!"
indicator. These widgets only appear on the current round's question screens;
past rounds render statically (issue 12).

Referenced in grill rounds: R3 (Q3.4 widget semantics), R5 (Q5.3 current
round is the only editable surface).

## Requirements

### Choice widget

- Exclusive choice: radio buttons binding to option ids (structural, issue 3).
- No default selection, no prefill — user must actively select.
- Exactly one choice per question.
- "Next" button is enabled only after a choice is made.
- "Skip" button (gray, next to Next) is always available; skipped questions
  are flagged in the result payload.
- Option labels render inline markdown (bold, links) from the payload.

### Comment widget

- Multi-comment list with add/remove per question.
- Zero comments is OK (except for "Other" — see below).
- Comments are free-text (plain text, not markdown-rendered on this screen;
  rendered on the recap screen E).
- Add: text input + submit button or Enter-to-add.
- Remove: per-comment delete button (DELETE endpoint, issue 8).

### "Other" option

- If the user selects "Other" (an option with `is_other` semantics), at
  least one comment is required before the question can proceed.
- The comment input becomes visually required (highlighted) when "Other" is
  selected.

### Autosave

- Debounced autosave: when the user makes a choice or adds/removes a comment,
  a POST to the answer endpoint (issue 8) fires after a short debounce
  (~500ms).
- A "Saved!" indicator appears briefly next to the top-right buttons on
  successful save, then fades.

### Navigation

- Sidebar (issue 8) lists the current round's questions; clicking a question
  navigates to its screen (back-navigation within the current round).
- "Next" advances to the next question or to the recap/submit screen (issue
  11) if it's the last question.

### Submission gating

- The recap/submit screen (issue 11) refuses submission if any question is
  unanswered (no choice made and not skipped).

## Dependencies

- Issue 3 (JSON schema — option ids, recommended_index)
- Issue 8 (HTML routes — question screen route, POST endpoints)
- Issue 9 (Tailwind — widget styling)

## Acceptance criteria

- Radio buttons bind to option ids; selecting one enables "Next".
- Comments can be added and removed; "Other" requires at least one.
- Autosave fires on change with a "Saved!" indicator.
- Sidebar lists current-round questions with working back-navigation.
- Skip marks the question as skipped in state.
- No prefill or default selection on any question.
